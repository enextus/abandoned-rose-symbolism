# Архитектура (3.0.0)

## Компоненты

| Класс | Ответственность |
|---|---|
| `RoseDrawing` | Публичный API, JPanel, история BACK/REDRAW/FORWARD, вращение мышью/клавишами, Turntable, Save PNG, фоновая отрисовка, CLI |
| `RoseRenderer` | Конвейер кадра: кэш геометрии + AO, камера (`Camera`), освещение, проекция, фон, растеризация, оверлеи |
| `RoseGeometry` | 3D-модель: спиральные лепестки, чашелистики, цветоложе, стебель с шипами, сложные листья, опавшие лепестки |
| `RoseMesh` | Растущая индексированная сетка: позиции, нормали, координаты поверхности (u, v / метрические hu, hv), материал, часть |
| `RoseLighting` | Карты теней (`ShadowMap`), ambient occlusion по 32 направлениям, повершинное освещение обеих сторон, тональная компрессия |
| `RosePalette` | Натуральные цвета роз в линейном RGB, альбедо всех материалов |
| `RoseRasterizer` | Параллельный по полосам отложенный растеризатор с суперсэмплингом и стилизацией сэмплов |
| `RoseBackdrop` | Java2D-слои: арка, нимб, фактура, трещины, контактные тени, роса, подпись |
| `RoseMath` | Матрицы 3 × 3, smoothstep, кривая ACES |
| `RoseDrawing_2` | Устаревшее имя запуска, делегирует `RoseDrawing.main` |

## Конвейер кадра

1. **Подготовка (кэш).** `RoseRenderer.prepare(seed, flower, detail)` строит сетку и считает AO. Ключ — seed, `FlowerOptions` и уровень детализации (0–2, зависит только от размера). LRU на 6 записей. Это самая дорогая часть, и она не зависит ни от ракурса, ни от стиля, ни от цвета.
2. **Ракурс.** Модель поворачивается вокруг вертикальной оси (yaw); камера поднимается/опускается (pitch). Свет закреплён относительно камеры, как в студии, поэтому роза всегда красиво освещена.
3. **Свет.** Две карты теней: ключевой свет 2048² (1024² для предпросмотра) и контровой 512². Повершинно для обеих сторон поверхности считаются: всё, кроме прямого ключевого света (`base`); прямой ключевой свет без тени (`key`); точка выборки тени (`shadowPos`).
4. **Проекция** в пространство холста 1000 × 1000 (центр цветка — (485, 352)), затем в сэмплы.
5. **Фон** (`RoseBackdrop.paintBase`): статические слои из кэша (размер, стиль, seed) + контактные тени, зависящие от ракурса.
6. **Растеризация** (`RoseRasterizer.render`): треугольники раскладываются по полосам по 16 строк; каждая полоса растеризуется независимо (целочисленные рёбра, правило top-left), хранит глубину, треугольник и барицентрики. Затем затеняются только видимые сэмплы: интерполяция, тень на сэмпл (фильтр 4 × 4), тональная компрессия, стиль. Пиксель — среднее `ss × ss` сэмплов в линейном свете поверх фона.
7. **Оверлеи:** роса (только на видимых, обращённых вверх точках лепестков), угловые метки, подпись.

## Потоки

- `renderScene` и весь конвейер потокобезопасны: кэши синхронизированы, буферы полос — `ThreadLocal`, полосы не делят изменяемых данных. Результат побитово одинаков на любом числе ядер (есть тест на `ForkJoinPool(1)`).
- Видимая панель рендерит в фоновом потоке `rose-render`. Одновременно считается не больше одного кадра, лишние запросы отбрасываются («побеждает последний»). Пока кадр готовится, показывается предыдущий, масштабированный.
- Отрисовка вне экрана (печать, тесты, `paint` в `BufferedImage`) остаётся синхронной и пиксель-в-пиксель совпадает с `renderScene`.
- Во время перетаскивания и Turntable запрашивается `Quality.PREVIEW` (1 сэмпл на пиксель, меньшая карта теней), после отпускания — `FINAL`.
- Все изменения состояния панели (`redraw`, `back`, `forward`, `setFlowerOptions`, `setView`, `setTurntable`) — только в EDT.

## Внешние зависимости

Runtime использует только Java SE (`java.desktop`). Maven нужен для тестов и покрытия. Скрипты `build.*` собирают JAR одним `javac` без сети.
