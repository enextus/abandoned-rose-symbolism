# Тестирование и покрытие

## Как проверялась версия 3.0.0

Среда, где готовилась 3.0.0, не имела доступа к Maven Central (403), поэтому `mvn clean verify` там запустить было нельзя. Вместо этого:

- исходники и тесты компилировались `javac --release 17 -Xlint:all` (без предупреждений);
- все JUnit-тесты выполнялись локальным совместимым раннером (те же аннотации `@Test`, `@ParameterizedTest`, `@CsvSource`, `@EnumSource`, `@TempDir`, те же `Assertions`), headless, как в Surefire;
- покрытие считалось собственным ASM-инструментатором строк и ветвей. Он строже JaCoCo: не фильтрует служебные ветви `switch` по строкам. Калибровка: на коде 2.5.0 он дал 96.4 % строк / 95.8 % ветвей при официальном JaCoCo 96.4 % / 97.4 %.

**Базовый результат 3.0.0: 80 тестов, 0 падений. Строки 98.6 %, ветви 94.8 % (порог pom.xml — 90 % / 90 %).**

Текущая тестовая база добавляет ещё один негативный I/O-кейс (итого ожидается 81 запуск): каталог назначения проверяется до `ImageIO`, поэтому ожидаемая ошибка сохранения больше не засоряет stderr внутренним stack trace JDK.

Официальный отчёт получите у себя:

```sh
mvn clean verify     # или test.sh / test.bat
```

Отчёт: `target/site/jacoco/index.html`. Старые папки `coverage-report/` и `test-results/` из поставки 2.5.0 удалены: они описывали прежний код.

## Что проверяется

Тесты организованы по контрактам через JUnit `@Nested`: rendering API, preview history, Swing UI, flower options и CLI. Swing-компоненты в проверках ищутся по accessibility-контрактам, а не по хрупким индексам `getComponent(n)`. Misleading-класс `RoseDrawingMockitoTest` удалён: Mockito в проекте не используется; smoke-проверка теперь называется `RoseSwingSmokeTest`.

`RoseDrawingTest` + `RoseSwingSmokeTest` (56 запусков): красная роза на тёмном фоне, детерминизм, валидация, стили, тон/seed, центрирование без растяжения, кэш панели, история BACK/REDRAW/FORWARD, кнопки, настройки цветка, CLI-экспорт, launcher.

`RoseRendererTest` (17 запусков):

- `View`: валидация, `turned` с переходом через 360° и ограничением наклона; ракурс меняет картину и воспроизводим;
- предпросмотр дешевле, но остаётся розой; выбор детализации и сглаживания;
- **побитовое совпадение на 1 ядре и на всех** (`ForkJoinPool(1)`);
- каждый стиль × каждая стадия: роса видна;
- большие изображения (> 2048 px) минуют кэш фона и совпадают;
- поля FADED_INK в его тоне;
- палитра: кольцо натуральных цветов, листья не перекрашиваются;
- тональная компрессия сохраняет оттенок и ограничена [0, 1];
- карта теней: под «крышей» темно, над ней светло, вне карты не затеняет, вырожденные случаи;
- AO: сердцевина получает меньше света неба, чем внешние лепестки;
- геометрия: детерминизм по seed, единичные нормали, детализация меняет только плотность, нормали трубок наружу, опавшие лепестки на земле, рост буферов сетки;

CLI-проверки перенесены в `RoseDrawingTest` / `Command-line contract`: экспорт сравнивается с `renderScene`, проверяются все флаги, неверные/пропущенные значения, legacy launcher, headless mode и чистые I/O-ошибки.

`RoseInteractionTest` (8): изменения ракурса только в EDT и вне истории; стрелки и Home; перетаскивание (кадры предпросмотра → полный кадр после отпускания), двойной щелчок; Turntable вращает и останавливается; **фоновая отрисовка**: до первого кадра фон, затем точные пиксели, при изменении размера масштабированный прежний кадр вместо пустоты, «побеждает последний»; `saveImage`; фоновое сохранение проверяет успешный файл, единственное user-facing сообщение при ошибке, отсутствие partial-файла и **чистый stderr без stack trace**; новые элементы панели.

`RoseRenderingCheck` — автономная проверка без JUnit (запуск `java ... org.example.RoseRenderingCheck`), проходит.

## Что не покрывается автоматически

Ветка открытия реального `JFrame` в `main` и диалог выбора файла `JFileChooser` (нужен дисплей). Реальное окно проверялось вручную под Xvfb: перетаскивание, Turntable, изменение размера, REDRAW; замеры блокировки EDT — в README.
